## Context

本變更把根目錄 DESIGN.md 的預定系統設計轉成可驗收需求。資料來源、工具介面、八大模組、Flowchart 與帶行號 Pseudocode 仍以根目錄 DESIGN.md 為完整工程說明。現階段只完成 Proposal。

## Goals / Non-Goals

目標：讓需求、工具、失敗分流、證據及驗收案例可互相對照；讓五個核心思維、三項取捨、十個問題能落到工程任務。

非本次目標：完成 Agent 程式、下載整份 BDG2、訓練模型、宣稱實驗結果或部署控制設備。

## Decisions

1. 工作流程依序為需求澄清 → 資料載入 → 品質檢查 → 基準與異常分析 → 依觀察選規則 → 報告驗證。LLM 不改動固定時間切分與門檻。
2. 使用 raw 電力資料並保留品質旗標；cleaned 僅供獨立敏感度分析，避免先移除欲研究的異常。
3. 主要基準採同星期×小時中位數；前 8 週訓練、2 週校準、2 週測試為暫定設定。測試期不參與擬合或調參。
4. 最多 10 次工具呼叫，暫時性 I/O 最多重試一次；缺欄位及品質不足須停止或補問。
5. 缺天氣時繼續用電分析但停用天氣規則；缺作息或可靠當地時間則停用作息規則。
6. 結論綁定 evidence_id、數值、單位、期間與來源；驗證失敗改用工具證據模板。

## Risks / Trade-offs

- 清理品質與保留異常衝突：保留原值加品質旗標，避免直接把可疑資料當設備故障。
- 準確與可解釋／成本衝突：先採可重現基準，再以獨立比較決定是否擴充模型。
- 固定流程與 Agent 彈性衝突：維持必要依賴，僅讓 Agent 選取符合前置條件的規則；以相同工具和資料比較。
